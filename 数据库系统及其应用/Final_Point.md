# 数据库系统概念解释

## 查询优化(QUERY OPTIMIZATION)

### 启发式方法(Heuristics)
==基于经验规则和直观判断的优化技术，用于在不完全探索所有可能执行计划的情况下，快速生成高效的查询执行方案。==
- **谓词下推(Predicate Pushdown)**：尽早执行过滤操作，将选择条件尽可能下推到数据源附近，减少后续处理的数据量。
- **投影下推(Projection Pushdown)**：尽早执行列裁剪操作，只选择查询所需的列，减少数据传输量。
- **连接重排序**
- **嵌套子查询重写与分解(Nested Sub-Queries: Rewrite and Decompose)**：将复杂的嵌套子查询转换为连接操作或其他更高效的执行形式。
    

### 统计信息(Statistics)

- **基数估计(Cardinality Estimation)**：预测查询操作返回的结果集大小，用于成本估算。
    
- **直方图(Histograms)**：用直方图表示数据分布，帮助优化器做出更好的决策。
    

### 基于成本的搜索(Cost-based search)

- **自底向上(Bottom-up)**：从底层操作开始构建执行计划，逐步组合。
    1. **扫描基表**：首先计算所有可能的基表访问方式（全表扫描、索引扫描等），并估算它们的成本。
    2. **逐步组合**：
    - 对单表操作（如 `WHERE` 过滤）生成候选计划，计算成本。
    - 对多表操作（如 `JOIN`），尝试不同的连接顺序和算法（嵌套循环、哈希连接、排序合并连接），计算每种组合的成本。
    3. **剪枝（Pruning）**：
    - 保留成本最低的部分计划，丢弃高成本的计划，减少搜索空间。
	4. **最终计划选择**：在所有候选计划中选择总成本最低的完整执行计划。
	优点：适用于动态规划，避免了重复计算（通过记忆化储存中间结果，提高效率）

- **自顶向下(Top-Down)**：从整体查询开始，逐步分解为子计划。
1. **从查询顶层开始**：优化器首先考虑整个查询的目标（如 `SELECT ... FROM ... WHERE ...`）。
2. **递归分解**：
    - 将查询分解为子查询（如先处理 `WHERE` 条件，再处理 `JOIN`）。
    - 对每个子查询生成候选执行计划，并计算成本。
3. **基于成本的剪枝**：
    - 如果某个子计划的成本已经高于已知最优计划，则放弃该路径（类似分支限界法）。
4. **组合最优子计划**：最终选择成本最低的完整执行计划。

- **更灵活**：可以结合启发式规则（如优先选择索引扫描）来引导搜索。
- **适用于复杂查询**：可以更好地处理子查询、视图展开等复杂情况。
- **可能重复计算**：如果没有良好的缓存机制，可能多次计算相同子问题的成本。
- **优化时间可能较长**：相比自底向上，可能需要更多递归调用。

### 冲突可串行化(Conflict Serializability)

- **正确性检查**：通过优先图(precedence graph)检测是否存在环。
    
- **等价性检查**：两个调度如果通过交换非冲突操作能够相互转换，则等价。
    
- **视图可串行化(View Serializability)**：比冲突可串行化更宽松的判定标准。
一个并发调度（Schedule）如果与某个串行调度（Serial Schedule）在最终数据库状态和所有事务的读取结果上完全一致，则该调度是视图可串行化的。

- **隔离级别与异常(Isolation Levels / Anomalies)**：不同隔离级别(如读未提交、读已提交、可重复读、串行化)可能导致的脏读、不可重复读、幻读等问题。

## 故障恢复(CRASH RECOVERY)

### 检查点(Checkpoints)
它周期性地将内存中的脏页和事务状态持久化到磁盘。

- **非模糊检查点(Non-Fuzzy)**：检查点时暂停所有事务，确保一致性状态。
    
- **模糊检查点(Fuzzy)**：检查点时允许事务继续执行，记录活跃事务状态。
	- **脏页表(Dirty Page Table)**：  
	    记录哪些页面被修改过及其最早的修改LSN(RecLSN)
	- **活跃事务表(Active Transaction Table)**：  
	    记录所有未提交的事务及其状态

### ARIES恢复算法

- **脏页表(Dirty Page Table, DPT)**：记录被修改但未写入磁盘的页面。
    
- **活跃事务表(Active Transaction Table, ATT)**：记录系统崩溃时未完成的事务。
    
- **恢复阶段**：分析阶段(确定需要重做和撤销的事务)、重做阶段(重做已提交事务的修改)、撤销阶段(回滚未完成事务的修改)。
    
- **日志序列号(Log Sequence Numbers, LSN)**：唯一标识日志记录。
    
- **补偿日志记录(Compensation Log Records, CLRs)**：记录撤销操作的特殊日志记录。
    - 特殊类型的日志记录
	- 记录撤销操作而非数据修改
	- 包含指向原日志记录的指针
	- 确保撤销操作只执行一次
	- 支持撤销过程的故障恢复
	- 维护事务原子性

## 连接算法(JOIN ALGORITHMS)

### 基本算法

- **简单嵌套循环(Naive Nested Loops)**：对左表每一行扫描整个右表。
r  + r * s
- **块嵌套循环(Block Nested Loops)**：将左表分块处理，减少右表扫描次数。
r + ⌈ r / (M-2) ⌉ * s
- **索引嵌套循环(Index Nested Loops)**：利用右表索引加速查找。
r + r * 索引查找成本

### 高级算法

- **排序归并(Sort-Merge)**：先对两表排序，然后归并连接。
|R|log|R| + |S|log|S|
O(|R| + |S|)
- **哈希连接(Hash Join)**：
    
    - 简单哈希(Simple)：构建内存哈希表。简单哈希连接是一种基于内存的连接算法，适用于参与连接的表（或其中一个表）能完全加载到内存的场景。它通过将较小的表构建成内存哈希表，然后用较大的表进行探测匹配，从而完成连接操作。
        |R| + |S|
        
    - 分区哈希(Partitioned)：处理大数据集时分区处理。分区哈希连接是处理大数据集的优化算法，通过将表按连接键哈希分区，使每个分区的数据量不超过内存限制，从而分而治之完成连接。
        2(|R| + |S|) (读写各一次)
        
    - 混合哈希(Hybrid Hash)：结合内存和磁盘处理。混合哈希连接结合了内存和磁盘处理，是前两种方法的折中方案，适用于部分数据可放入内存、部分需溢出到磁盘的场景。
        (|R| + |S|)(1 + (1 - mem_size/total_size))
- **布隆过滤器优化(Bloom Filters)**：使用概率数据结构快速过滤不可能匹配的记录。
    

### 成本函数(Cost functions)

计算不同连接算法的I/O和CPU开销，用于优化器选择最佳算法。

## 期中前内容(STUFF BEFORE MID-TERM)

### 核心概念

- **SQL**：结构化查询语言，数据库操作的标准语言。
    
- **缓冲池管理(Buffer Pool Management)**：管理内存中数据库页面的缓存策略。
    
- **数据结构**：
    
    - 哈希表(Hash Tables)：快速查找的数据结构。
        
    - B+树(B+Trees)：数据库索引的常用结构。
        
- **存储模型(Storage Models)**：行存储、列存储等数据组织方式。
    
- **查询处理模型(Query Processing Models)**：如火山模型、物化模型等。
    
- **查询间并行(Inter-Query Parallelism)**：同时执行多个查询的并行处理。
