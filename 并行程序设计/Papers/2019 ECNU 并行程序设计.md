### 四、程序题（20 分）

使用 OpenMP 实现生产者 - 消费者程序。其中一些线程是生产者，另外一些线程是消费者。它们将读出的文本行插入到一个共享的队列中。消费者从队列中取出文本行，并对文本行进行分词。符号是被空白符分开的单词，当消费者发现一个单词后，它将该单词输出到 stdout。（要求：输出的单词需要给出是哪个线程输出的）




### 答案：

#### 一、不定项选择题

1. **答案**：C **解析**：并行程序主要目的是提高系统运行速度和处理能力 ；并行程序不一定能减小执行开销，也并非必然要求资源共享，和电源管理能力没有直接关联。
2. **答案**：B **解析**：写 - 写数据依赖关系指对同一变量有多个写操作且存在先后顺序影响结果 ，A 选项不存在写 - 写依赖；C 是写 - 读依赖；D 是写 - 读依赖（这里写操作顺序交换不影响结果，但本质是写 - 读依赖逻辑），只有 B 选项中 a 和 b 的写操作存在相互影响的写 - 写依赖。
3. **答案**：A **解析**：共享内存系统中处理器共享同一地址空间，并非拥有自己独立地址空间 ；处理器间通过隐式通信共享数据，线程间通过共享变量的锁和屏障协调，每个处理器可访问共享内存任何位置。
4. **答案**：A、C **解析**：在 OpenMP 中，shared variables（共享变量） 、static variables（静态变量）默认是共享的；loop index（循环索引）一般是私有的，private variables（私有变量）是私有的。
5. **答案**：A、B、D **解析**：消息传递是共享内存并行编程替代方案，没有数据竞争问题 ，消息传递库调用在单处理器上也可运行；消息传递是可移植的。

#### 二、简答题

1. **答案**：死锁是指在一组进程中的各个进程均占有不会释放的资源，但因互相申请被其他进程所占用不会释放的资源而处于的一种永久等待状态 。例如，进程 A 持有资源 R1，等待资源 R2，进程 B 持有资源 R2，等待资源 R1，两个进程都无法继续执行，陷入死锁。
2. **答案**：
    - **直接映射**：主存中的每一块只能映射到 Cache 的一个特定位置。将主存地址按 Cache 大小分区取模，计算出对应 Cache 行号。优点是硬件实现简单，缺点是冲突概率高。
    - **全相联映射**：主存中的任意一块可以映射到 Cache 的任意一块位置。通过地址标签比较来确定是否命中，优点是冲突概率低，缺点是硬件实现复杂，速度慢，成本高。
    - **组相联映射**：是直接映射和全相联映射的折中。将 Cache 分成若干组，主存块映射到 Cache 组是固定的（类似直接映射），但在组内可以任意映射（类似全相联映射） 。这种方式兼顾了硬件复杂度和冲突概率。
3. **答案**：指令级并行的流水线多发射机制是指在一个时钟周期内从流水线的发射段同时发射多条指令到不同功能部件执行，以提高指令执行并行度。
    - **超标量发射**：在每个时钟周期从指令流水线的发射段同时发射多条指令到不同功能部件执行，处理器内部有多个功能部件和指令译码逻辑，能同时处理多条指令。
    - **超长指令字**：将多条能并行执行的指令组合成一条具有多个操作段的超长指令字，由编译器在编译时将可并行的操作组合在一起，硬件只需简单地按字段执行相应操作。

#### 三、分析题

1. - **答案**： 每个处理器执行指令时间 \(t_{instruction}=\frac{10^{12}/1000}{10^{14}} = 0.01\) 秒， 每个处理器发送消息时间 \(t_{message}=10^{6}(1000 - 1)\times10^{- 3}\approx10^{6}\) 秒， 总时间由发送消息时间主导，约为 \(10^{6}\) 秒。
    - **解析**：先计算每个处理器执行指令时间，根据单处理器速度和分配指令数计算；再计算每个处理器发送消息时间，根据消息条数和发送每条消息时间计算，总时间取决于两者中较大值。
    - **答案**： 每个处理器执行指令时间 \(t_{instruction}=\frac{10^{12}/1000}{10^{14}} = 0.01\) 秒， 每个处理器发送消息时间 \(t_{message}=10^{6}(1000 - 1)\times10^{-3}\approx10^{6}\) 秒， 总时间由发送消息时间主导，约为 \(10^{6}\) 秒。
    - **解析**：同第一小问，先算执行指令时间，再算发送消息时间，取较大值为总时间。
2. **答案**： 画图略（因无法直接绘制，这里简述思路） 。
    - **MPI.Scatter**：以进程 0 为根节点构建 8 个节点（对应 8 个进程）的树形结构，将 16 个元素的数组按一定规则（如平均分配）从进程 0 向其他 7 个进程分发，每一层节点代表一次数据传递过程，从根节点开始向下逐层传递数据。
    - **MPI.Gather**：同样以进程 0 为根节点构建树形结构，8 个进程将各自拥有的数组元素向进程 0 汇聚，从叶子节点开始逐层向上传递数据，最终在进程 0 保存所有元素。

#### 四、程序题

cpp

运行

```cpp
#include <iostream>
#include <sstream>
#include <string>
#include <queue>
#include <omp.h>

std::queue<std::string> sharedQueue;
omp_lock_t queueLock;

// 生产者线程函数
void producer(int id) {
    std::string textLine;
    std::cout << "Producer " << id << " input text line: ";
    std::getline(std::cin, textLine);

    omp_set_lock(&queueLock);
    sharedQueue.push(textLine);
    omp_unset_lock(&queueLock);
}

// 消费者线程函数
void consumer(int id) {
    while (true) {
        omp_set_lock(&queueLock);
        if (!sharedQueue.empty()) {
            std::string textLine = sharedQueue.front();
            sharedQueue.pop();
            omp_unset_lock(&queueLock);

            std::istringstream iss(textLine);
            std::string word;
            while (iss >> word) {
                std::cout << "Consumer " << id << " output word: " << word << std::endl;
            }
        } else {
            omp_unset_lock(&queueLock);
            break;
        }
    }
}

int main() {
    int numProducers = 2;
    int numConsumers = 2;

    omp_init_lock(&queueLock);

    #pragma omp parallel num_threads(numProducers + numConsumers)
    {
        int threadId = omp_get_thread_num();
        if (threadId < numProducers) {
            producer(threadId);
        } else {
            consumer(threadId - numProducers);
        }
    }

    omp_destroy_lock(&queueLock);
    return 0;
}
```

  

**解析**：

  

1. 定义共享队列 `sharedQueue` 存放文本行，使用 OpenMP 的锁 `omp_lock_t queueLock` 保护共享队列操作。
2. `producer` 函数中，生产者线程获取用户输入文本行，加锁后将文本行放入共享队列。
3. `consumer` 函数中，消费者线程不断尝试从共享队列取文本行，加锁判断队列非空后取出，对文本行分词并输出单词，同时标识是哪个消费者线程输出。
4. `main` 函数中，初始化锁，通过 OpenMP 并行区域创建生产者和消费者线程，根据线程编号调用相应函数，最后销毁锁。
