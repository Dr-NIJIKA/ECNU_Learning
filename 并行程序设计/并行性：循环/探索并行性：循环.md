## 数据依赖
如果两个存储访问操作访问相同的存储位置（同一个变量），其中一个访问是写（或更新）操作，则两个操作间存在数据依赖（有点像Database的冲突？）

数据依赖关系体现了两个存储访问操作的执行顺序
两个不同的程序语句之间可能存在数据依赖关系，同一程序语句的两个不同的动态执行之间也可能存在数据依赖关系

![[Pasted image 20250611104838.png]]

i 和 i' 访问同一个变量（或者同一个存储位置）；至少其中一个是写操作

Ij 是进程Pj要读的数据集合，Oj是进程Pj要写的数据集合。如果进程Pj和另一个进程Pk可以并行执行, 则
                           Ij ∩ Ok = Ik ∩ Oj  = Oj ∩ Ok = ϕ
也就是说，进程Pj和进程Pk的读和写，写和读，写和写都要交集为空。

## 循环数据依赖
#### 考虑局部性：
- 关注处理器对本地缓存的数据访问
- 考虑处理器内部缓存和寄存器中的数据局部性
- 降低存储访问开销
- 最大化存储访问宽带

#### 数据重用：
**数据重用**：相同数据或者相邻数据被多次使用。数据重用是计算固有的性质。
**数据局部性**：被重用的数据存储在较快的存储器中（缓存或寄存器）
可以通过适当的数据分配和防止，代码的重排转换来获得更好的局部性
```C
for (i=1; i<N; i++)
	for (j=1; j<N; j++)
		A[j]= A[j+1]+A[j-1]；
```
这里Aj在外层循环i，在不同迭代（时间）中被重复使用
Aj所在的缓存行（空间）在内存循环中被反复使用

### 循环中的数据依赖
#### 循环体依赖
不同迭代间存在数据依赖
#### 循环无关依赖
迭代内存在数据依赖
#### 如何判断：
利用迭代空间（Iteration Space），结合循环语句找到依赖关系
- 以空间形式显性的表示循环迭代
![[Pasted image 20250611110730.png]]
**迭代实例（ Iteration instance ）**：用迭代空间中的坐标来表示，例如[1,1] 表示i=1，j=1的迭代实例
**字典序（Lexicographic order）**：迭代的串行执行顺序，例如[0,0], [0,1], ..., [0,6],[1,1], [1,2], [1,3], ..., [1,6], ...
**字典序小于（lexicographically less than）**：当且仅当存在[i1, i2,…, ic-1] = [i’1, i’2,…, i’c-1]并且ic< i’c，迭代I字典序小于I’，表示为I<I’。
**从左到右比较，优先变化最右侧的循环变量**（即内层循环）。  
用数学符号表示：  
(i1,j1)<lex(i2,j2)(i1​,j1​)<lex​(i2​,j2​) 当且仅当：
1. i1<i2i1​<i2​，**或**
2. i1=i2i1​=i2​ 且 j1<j2j1​<j2​。

**距离向量** Distance Vectors：简明地描述一个迭代空间的迭代之间的依赖关系
距离向量D=I’- I=[1,1]（前面是外层循环，后面是内层循环）
距离值是存在数据依赖的迭代间相隔的迭代数量
==直接找到源迭代和目标迭代，做差，注意外层和内层循环的关系==

#### 距离向量与数据依赖合法性
♦循环转换必须保证数据依赖保持不变
♦字典序非负（lexicographically nonnegative）：
- 距离向量的最左边元素为正数，
- 或者距离向量所有元素都为0。
♦当字典排序非负时，依赖关系是合法的
- 迭代I不能依赖于后面执行的迭代I’，即如果I<I’那么不存在迭代I’到迭代I的数据依赖

#### 方向向量
方向向量与距离向量一样，用来表示循环体依赖
方向向量的每个元素为<、>或 =：
- <：迭代I到I’ 存在循环体依赖且I<I’；
- >：迭代I到I’ 存在循环体依赖且I>I’；
- =：循环无关依赖

♦例如：距离向量为[1,1]，那么方向向量为[<,<]
==♦合法循环体依赖的方向向量：([=,=],[=,<], [<,=], [<,<],[<,>])
♦不合法循环体依赖的方向向量：([=,>],[>,<], [>,=], [>,>])==

## 循环转换
用于组织计算序列和内存访问序列，以更好地适应多核处理器的内部结构以及指令级并行。
#### 循环交换（Loop Interchange）
交换循环的顺序来改变数据遍历的顺序。
- 交换内外层排序
除了<>,其余所有含有>的都不合法，剩下的合法
#### 循环分块（Loop Tile）
重排循环迭代，让有数据重用的迭代相继执行
优化缓存、寄存器等容量有限的存储设备的数据重用

循环分块方法：采用strip-mine-and-interchange分块法
首先进行strip-mine（分块执行），增加循环层次
然后进行interchange，使循环分块执行

#### 循环展开（Loop unroll）
简单的将多个循环展开到一个循环内
♦展开不超过原始循环的迭代次数就是安全的。
♦展开增加了循环内部的并行度
♦减少了循环次数即减少了控制语句，提升性能
![[Pasted image 20250611161220.png]]
**物理限制**：
代码大小受限于内存和缓存容量，过度展开会导致指令缓存失效。
寄存器数量有限（如x86仅有16个通用寄存器），展开过多会引发寄存器溢出（Spill）。

**收益递减**：
当展开因子 kk 超过一定阈值（如 k=8k=8），性能提升趋缓甚至下降。

**依赖约束**：
若存在循环携带依赖（如 `A[i] = A[i-1] + 1`），无限展开会破坏语义正确性。

#### 循环融合（Loop Fusion）
就是将多个循环融合在一起。
